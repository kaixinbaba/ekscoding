# Logic Map README

本目录记录项目的业务功能逻辑。它面向二次开发、需求评审、Bug 排查和 Agent 交接，不面向源码讲解。

## 使用方式

- 从 `docs/LOGIC_MAP.md` 进入，先判断需求属于哪个模块。
- 进入模块索引页，通过编号段分配表找到对应的二级文档。
- 修改代码前，**必须**追踪到二级文档，阅读完整的页面入口、服务端入口、调用顺序、流程图和异常边界。
- 修改代码后，检查对应二级文档和模块索引页是否仍然准确。
- 如果一次改动跨模块，所有受影响模块的二级文档都要更新。
- 新增二级文档或模块时，使用 `templates/` 下的模板。

## 文档边界

逻辑地图应该写：

- 用户从哪个页面或 API 进入。
- 用户动作触发哪个客户端组件、Action、Route Handler 或 Provider。
- 服务端会读写哪些业务状态。
- 结果会回到哪个页面、Toast、跳转、邮件、通知或 webhook。
- 哪些配置开关会改变可见入口或流程分支。

逻辑地图不应该写：

- 源码片段。
- 组件内部渲染细节。
- 样式实现。
- 普通工具函数的逐行行为。
- 与业务调用关系无关的重构说明。

## 文档结构

逻辑地图采用两层文档结构：

- **根索引**：`docs/LOGIC_MAP.md` — 只展示全貌、模块总览表、全局调用图和阅读顺序。
- **模块索引页**：如 `A-global-routing.md` — 声明本模块编号段分配，链接到二级文档。不展开具体流程。
- **二级文档**：如 `A-global-routing/routing-i18n.md` — 承接一个业务子域的完整调用链路，包含入口表、调用顺序、流程图、异常边界和维护清单。
- **规范与模板**：
  - `NUMBERING.md`：统一编号规范，覆盖模块索引页和二级文档的编号规则。
  - `templates/MODULE_TEMPLATE.md`：模块索引页模板（X0 总览 + 编号段分配表 + 迁移记录）。
  - `templates/SECOND_LEVEL_TEMPLATE.md`：二级文档模板（Xn.0-Xn.9 全编号段，无代码片段）。
